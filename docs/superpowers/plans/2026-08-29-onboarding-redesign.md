# Onboarding Redesign (2.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move account creation from the first screen to the end of onboarding, so a new user reaches a populated Today screen with their own medication before being asked for an email address.

**Architecture:** `RootView`'s gate order inverts — auth stops being the first gate and becomes a destination reached at step 9. A new `OnboardingFlow` owns step sequencing and skip handling; each step reuses an existing view rather than reimplementing it. Guest-to-account upgrade gets an explicit merge choice so locally-entered medications are never silently discarded.

**Tech Stack:** SwiftUI (iOS 17+), CoreData, Supabase Swift SDK, XCTest. Project files are generated by XcodeGen from `project.yml`.

**Spec:** `docs/superpowers/specs/2026-08-28-onboarding-redesign-design.md`

**Out of scope for this plan:** the visual refresh and new app icon. Those are asset work with a different review shape and get their own plan (`2026-08-29-onboarding-visual-refresh.md`). This plan must not change any mascot asset.

## Global Constraints

- **iOS 17.0 minimum.** SwiftUI, MVVM. No new third-party dependencies.
- **Critical Rule 6 (CLAUDE.md §15):** the medical disclaimer must remain mandatory and *recorded*, never a dismissible banner. It stays a hard gate.
- **Critical Rule 5:** never delete a medication without a confirmation step. This governs the merge screen.
- **Existing users must be unaffected.** Anyone with `hasCompletedOnboarding == true` routes straight to the app.
- **Reuse, don't reimplement.** `AddEditMedicationView`, `DisclaimerConsentView`, `AuthView`, `ContraceptiveTrackerView` are used as-is. If a variant presentation is needed, add a parameter to the existing view.
- **No new sensitive data.** No gender/pronoun field. `PrivacyInfo.xcprivacy` must not change.
- **Copy constraint:** a subscription is tied to the user's Apple ID and restores without an account. Copy may say "your medications aren't backed up". Copy must NEVER imply DoseTrack Plus itself would be lost.
- **After creating or deleting any file, run `xcodegen generate`.** `project.yml` is the source of truth; the `.xcodeproj` is generated and must never be hand-edited.
- **Version for release: 2.0** (`MARKETING_VERSION` in `project.yml`). Do not bump it until the final task.
- **Test isolation:** tests that touch `UserDefaults` must use a named suite and clear it in `setUp`/`tearDown`, never `.standard`. Follow `DoseTrackTests/ReviewPromptManagerTests.swift`.

```swift
// DoseTrack/Views/Onboarding/OnboardingStep.swift
import Foundation

/// The onboarding sequence, as a pure rule.
///
/// Kept free of SwiftUI so the order — the part most likely to be got wrong, and the part a
/// reviewer most needs to be able to check — is testable on its own. `OnboardingFlow` owns
/// presentation; this owns "what comes next".
enum OnboardingStep: Equatable, CaseIterable {
    case welcome
    case profile
    case disclaimer      // hard gate: consent before any medication data (Critical Rule 6)
    case addMedication
    case reminders
    case tour
    case addAnother
    case birthControl
    case accountOffer

    /// `nil` means onboarding is complete.
    ///
    /// - Parameter didAddMedication: whether the user has actually added one. Reminders and the
    ///   tour are skipped when they haven't — a soft prompt naming no medication, and a tour of
    ///   an empty Today screen, are both worse than nothing.
    static func next(after step: OnboardingStep, didAddMedication: Bool) -> OnboardingStep? {
        switch step {
        case .welcome:        return .profile
        case .profile:        return .disclaimer
        case .disclaimer:     return .addMedication
        case .addMedication:  return didAddMedication ? .reminders : .birthControl
        case .reminders:      return .tour
        case .tour:           return .addAnother
        case .addAnother:     return .birthControl
        case .birthControl:   return .accountOffer
        case .accountOffer:   return nil
        }
    }

    /// Where "Add another" sends the user. Deliberately a named function rather than a branch in
    /// `next(after:)`: the loop targets the add form ALONE, and reminders/tour must not repeat.
    static func loopingBackToAddAnother() -> OnboardingStep { .addMedication }

    /// The skip affordance is always visible where it exists, and never asks for confirmation —
    /// a tour you cannot leave is a trap, and this redesign exists to remove walls.
    var isSkippable: Bool {
        switch self {
        case .welcome, .profile, .disclaimer: return false
        case .addMedication, .reminders, .tour, .addAnother, .birthControl, .accountOffer: return true
        }
    }
}
```

```swift
// DoseTrack/Views/Onboarding/OnboardingFlow.swift
import SwiftUI

/// Sequencing state for onboarding. Knows the order and what has already been shown; knows
/// nothing about how any individual step renders.
///
/// `shownOnce` is what makes the step 7 "add another" loop behave: the loop targets the add
/// form alone, so reminders and the tour must not replay on the second and later passes.
@MainActor
final class OnboardingFlowState: ObservableObject {

    @Published private(set) var step: OnboardingStep = .welcome
    @Published private(set) var isComplete: Bool = false
    private(set) var medicationsAdded: Int = 0

    private var shownOnce: Set<OnboardingStep> = []

    func recordMedicationAdded() {
        medicationsAdded += 1
    }

    func advance() {
        guard !isComplete else { return }
        shownOnce.insert(step)
        move(to: OnboardingStep.next(after: step, didAddMedication: medicationsAdded > 0))
    }

    func skipCurrent() {
        advance()
    }

    /// Step 7's loop. Returns to the add form without clearing `shownOnce`, so the already-seen
    /// reminder prompt and tour are stepped over on the way back down.
    func addAnother() {
        step = OnboardingStep.loopingBackToAddAnother()
    }

    func finish() {
        isComplete = true
    }

    private func move(to next: OnboardingStep?) {
        guard var candidate = next else { finish(); return }
        // Step over anything already shown (reminders, tour) on a second pass.
        while shownOnce.contains(candidate) {
            guard let following = OnboardingStep.next(after: candidate,
                                                      didAddMedication: medicationsAdded > 0) else {
                finish(); return
            }
            candidate = following
        }
        step = candidate
    }
}
```

```swift
// DoseTrack/Views/Onboarding/RootGate.swift
import Foundation

/// Which top-level screen RootView should show.
///
/// Extracted as a pure function for two reasons. It is the redesign's central architectural
/// change (auth is no longer the first gate), and the previous inline if/else chain had a path
/// where every branch failed and SwiftUI rendered nothing — a permanent blank screen (fixed in
/// 70bc76d). `resolve` is total: every input combination returns a renderable case.
enum RootGate: Equatable {
    case onboarding
    case resolvingDisclaimer
    case disclaimer
    case app

    static func resolve(
        hasCompletedOnboarding: Bool,
        disclaimerStatus: DisclaimerManager.Status,
        hasActiveAccount: Bool
    ) -> RootGate {
        guard hasCompletedOnboarding else { return .onboarding }

        switch disclaimerStatus {
        case .required: return .disclaimer
        case .unknown:  return .resolvingDisclaimer
        case .accepted: break
        }

        // No account context yet — re-run onboarding rather than render nothing. Onboarding is
        // cheap to re-enter and self-heals the state; a blank screen strands the user forever.
        return hasActiveAccount ? .app : .onboarding
    }
}
```

```swift
/// Hosts the onboarding sequence. Owns presentation and the skip affordance; `OnboardingFlowState`
/// owns the order. Every step reuses an existing view rather than reimplementing it.
struct OnboardingFlow: View {

    let onFinished: () -> Void

    @StateObject private var state = OnboardingFlowState()
    @EnvironmentObject private var auth: AuthManager
    @Environment(\.managedObjectContext) private var context
    @ObservedObject private var disclaimer = DisclaimerManager.shared

    var body: some View {
        ZStack {
            Color(.systemBackground).ignoresSafeArea()
            content
        }
        .animation(.easeInOut(duration: 0.3), value: state.step)
        .overlay(alignment: .topTrailing) {
            if state.step.isSkippable {
                // Always visible, never confirmed: a flow you cannot leave is a trap.
                Button("Skip") { state.skipCurrent() }
                    .font(.subheadline.weight(.semibold))
                    .padding()
            }
        }
        .onChange(of: state.isComplete) { _, complete in
            if complete { onFinished() }
        }
    }

    @ViewBuilder
    private var content: some View {
        switch state.step {
        case .welcome:
            WelcomePage(onContinue: { state.advance() })

        case .profile:
            ProfileSetupPage(onContinue: { state.advance() })

        case .disclaimer:
            // Hard gate (Critical Rule 6). Accepted locally here; recorded to the account later
            // if one is created at step 9. Declining cannot proceed — there is nothing to sign
            // out of yet, so it returns to the welcome step.
            DisclaimerConsentView(
                onAccept: {
                    Task {
                        await disclaimer.accept(userId: nil, isGuest: true)
                        state.advance()
                    }
                },
                onDecline: { state.restart() }
            )

        case .addMedication:
            AddEditMedicationView(medication: nil)
                .environment(\.managedObjectContext, context)
                .onDisappear {
                    // AddEditMedicationView dismisses itself on save; treat a saved medication
                    // as the signal to move on.
                    state.advance()
                }

        case .reminders, .tour, .addAnother, .birthControl, .accountOffer:
            // Implemented in Tasks 5-8. Advancing keeps the flow traversable meanwhile.
            Color.clear.onAppear { state.advance() }
        }
    }
}
```

```swift
// DoseTrack/Services/AccountPromptScheduler.swift
import Foundation

/// Decides whether to ask a local-only user again about creating an account.
///
/// Declining at the end of onboarding is respected: exactly one reminder follows, two weeks
/// later, framed on what is by then at stake. A second decline silences it permanently. The only
/// place the subject may come up afterwards is the Plus upgrade path.
///
/// Shaped after `ReviewPromptManager`: small, pure, injectable defaults so it is testable.
final class AccountPromptScheduler {

    static let shared = AccountPromptScheduler()

    static let daysUntilReAsk = 14
    private static let maximumDeclines = 2

    private let defaults: UserDefaults

    private enum Key {
        static let declineCount = "accountPrompt.declineCount"
        static let lastDeclined = "accountPrompt.lastDeclinedAt"
    }

    init(defaults: UserDefaults = .standard) {
        self.defaults = defaults
    }

    var isSilencedForever: Bool {
        defaults.integer(forKey: Key.declineCount) >= Self.maximumDeclines
    }

    func recordDeclined(now: Date = Date()) {
        defaults.set(defaults.integer(forKey: Key.declineCount) + 1, forKey: Key.declineCount)
        defaults.set(now.timeIntervalSince1970, forKey: Key.lastDeclined)
    }

    func shouldPromptAgain(now: Date = Date()) -> Bool {
        guard !isSilencedForever else { return false }
        let last = defaults.double(forKey: Key.lastDeclined)
        guard last > 0 else { return false }   // never declined: onboarding hasn't asked yet
        let elapsed = now.timeIntervalSince(Date(timeIntervalSince1970: last))
        return elapsed >= Double(Self.daysUntilReAsk) * 86_400
    }

    func resetForTesting() {
        defaults.removeObject(forKey: Key.declineCount)
        defaults.removeObject(forKey: Key.lastDeclined)
    }
}
```

```swift
// DoseTrack/Services/LocalDataMerge.swift
import Foundation

enum MergeOutcome: Equatable {
    /// Local data is the only data — push it up and carry on.
    case keepLocalAndPush
    /// Both sides have medications. Genuinely ambiguous, so the user decides.
    case askUser
    /// Nothing local to preserve.
    case nothingToDo
}

/// What happens to locally-entered medications when a local-only user signs in.
///
/// Under the 2.0 onboarding every user starts local with real medications, so this path is the
/// main road rather than an edge case. Two rules are load-bearing:
///
/// 1. **Never discard silently.** Remote-wins would delete medications the user just typed in —
///    unacceptable for a medical app and a direct violation of Critical Rule 5.
/// 2. **Never wipe the local store on an upgrade.** `signOut()` wipes deliberately; an upgrade
///    is not a sign-out and must not borrow that behaviour.
enum LocalDataMerge {

    static func outcome(localMedicationCount: Int, remoteMedicationCount: Int) -> MergeOutcome {
        guard localMedicationCount > 0 else { return .nothingToDo }
        return remoteMedicationCount > 0 ? .askUser : .keepLocalAndPush
    }

    /// Always false. Present as a named function so the guarantee is explicit and testable
    /// rather than an absence someone can accidentally fill in later.
    static func mustWipeLocalStore(for outcome: MergeOutcome) -> Bool {
        false
    }
}
```

## Task 10: Fix network-gated sign-out

Recorded in the spec's Risks as a known defect left deliberately unfixed. It becomes load-bearing now that real-account sign-out is common.

**Files:**
- Modify: `DoseTrack/Services/AuthManager.swift` (`signOut()`, currently around lines 160–173)

> **The defect:** `session = nil` sits *after* `try await client.auth.signOut()`. The Supabase SDK's `signOut(scope:)` removes the local session and then POSTs to `/logout`, awaiting the response before returning (`supabase-swift/Sources/Auth/AuthClient.swift:972`). Offline, that await can hang, so `session` stays non-nil, `RootView` keeps rendering the app, and the Sign Out button appears to do nothing.

- [ ] **Step 1: Reorder so local state clears first**

Replace the body of `signOut()` in `DoseTrack/Services/AuthManager.swift` with:

```swift
    func signOut() async {
        isLoading = true
        defer { isLoading = false }

        GuestMode.deactivate()

        // Clear LOCAL state before the network call, not after. The Supabase SDK's signOut()
        // POSTs to /logout and awaits the response; offline that can hang indefinitely, and
        // while it did, `session` stayed non-nil and RootView kept showing the app — the Sign
        // Out button appeared to do nothing. Signing out is a local decision; the server call
        // is best-effort cleanup.
        session = nil
        PersistenceController.shared.wipeLocalStore()
        UNUserNotificationCenter.current().removeAllPendingNotificationRequests()
        WidgetCenter.shared.reloadAllTimelines()

        do {
            try await client.auth.signOut()
        } catch { /* local session already cleared; server-side revocation is best-effort */ }
    }
```
